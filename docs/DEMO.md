# Docker Judge Demo

The canonical local judge environment is the root Compose configuration:

```bash
git clone https://github.com/riyannode/horoizec.git
cd horoizec
docker compose up --build
```

Open [http://localhost:3000/demo](http://localhost:3000/demo). Docker Engine and Compose v2 are the only runtime prerequisites. Build stages use pinned Rust/Bun versions and the checked-in Cargo/Bun lockfiles. No `.env`, QEDIT RPC, wallet, payment, public-chain scan, migration command, or blockchain transaction is needed.

## What the page verifies

- **Valid proof:** the backend loads `backend/fixtures/judge-hcp1.json`, derives its immutable statement through Rust, and verifies HCP1 with the native `horoi-verifier`. Startup fails if that proof or its alternate nullifier does not verify.
- **Tampered proof:** the backend flips one byte in the proof transcript and passes the result through that same verifier. The page reports rejection only when Rust returns `INVALID_PROOF`.
- **Replay:** each submission verifies the original HCP1 proof, then atomically inserts its claim-specific alternate nullifier in SQLite. The first clean submission returns HTTP 201; the identical second submission returns HTTP 409 `NULLIFIER_USED`.
- **Privacy boundary:** the frontend receives the public statement and result, never the proof fixture, spending key, private note value, or witness.

The fixture is a **LOCAL SYNTHETIC TEST FIXTURE**, generated by Horoi's existing Rust scanner test utility from local Orchard test notes. Its protocol `networkId` is `zebra-regtest`; the committed local roots were not read from a Zebra node, QEDIT public testnet, or public chain. It demonstrates real HCP1 verification, not public-chain ownership or a public-testnet E2E. The fixture contains only the HCP1 bundle and public statement fields, not its test witness or spending key.

Fixture SHA-256: `2fb21151e3dc2413b041b2509a10f6e6b408b1e599b32aa5e5671ba0b2e21554`.

The `/demo` walkthrough is an authorized judge-only addition to the original five-route MVP PRD. Fixture verification is server-side and separate from `/claims/[id]` browser-local proof generation. In Docker judge mode, chain-dependent creation and action-fetch endpoints are read-only/disabled to prevent accidental external scans.

Replay state persists in the project-scoped SQLite volume. To return to the initial state, stop and remove only this Compose project's resources:

```bash
docker compose down -v --remove-orphans
docker compose up --build
```

The Compose project name is `horoi-judge`; it does not remove other project volumes, networks, or containers.
